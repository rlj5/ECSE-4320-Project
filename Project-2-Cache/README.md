# ECSE 4320/6320 Project 2: Cache and Memory Performance Profiling (Ryzen 7 5825U, WSL2)

Latency, bandwidth and concurrency of the memory hierarchy with custom benchmarks: zero-queue latency per level, pattern/granularity/stride sweeps, read/write mixes,
throughput-latency curves with Little's Law, working-set / cache / TLB analysis (4 KiB pages vs transparent huge pages), and benchmark pitfalls.

| file | purpose |
|---|---|
| `HYPOTHESES.md` | pre-experiment predictions |
| `REPORT.md` | completed report with results, analysis, limitations, and evidence links |
| `src/memlat.c` | pointer-chase latency tool: random/sequential, granularity, K chains, THP on/off, clock estimator |
| `src/membw.c` | multi-thread bandwidth + loaded-latency tool (AVX2 line operations, probe thread, injected delay) |
| `src/stream_triad.c` | independent STREAM-style OpenMP triad (cross-check) |
| `preflight.sh` | checks WSL2, memory, THP, perf, power, load; writes `env/preflight.txt` |
| `build.sh` | compiles the three tools |
| `run_experiments.py` | all experiments -> `data/raw/*.csv` (`--quick`, `--only a,b`, `--tag NAME`) |
| `plot_all.py` | figures -> `plots/`, processed data -> `data/processed/` (includes AMAT model and timing-based miss inference) |
| `make_results_tables.py` | `RESULTS_TABLES.md`: every number quoted in the report |
| `collect_env.sh`, `run_all.sh` | environment capture; everything in order |
| `pitfall_freq.sh` | frequency pitfall with cpufreq (needs native Linux + root; not available in WSL2) |

## Run (Windows 11 + WSL2 Ubuntu 24.04)
```bash
sudo apt update && sudo apt install -y build-essential python3-pandas python3-matplotlib python3-tabulate
chmod +x *.sh *.py
./preflight.sh                      # read the warnings; write the Windows-side facts (RAM type/speed, power mode) down
./run_all.sh --quick                # smoke test (about 10-15 min): check that plots/ look sane and thp_kb > 0 in data/raw/tlb.csv
./run_all.sh                        # full run, expect 30-60 min; do not use the laptop meanwhile
```
The primary full-suite results were run with Windows **Best performance** and **Energy Saver off** (operator-confirmed; the WSL2 capture cannot read these Windows settings). A zero-queue comparison was also run with Windows **Balanced** and **Energy Saver on**; it is included as `zero_queue_saver.csv` and summarized in the report. The comparison covers zero-queue latency only, not the full suite. For a controlled repeat, use AC power, close browsers and Docker Desktop (load average under 0.5 in `preflight.sh`), and keep at least 3.5 GiB free in WSL2.
If `./run_all.sh` fails half way, run the missing experiments with `python3 run_experiments.py --only name` (names: crosscheck zero_queue ws_sweep pattern rw_mix intensity intensity_seq chains cache_miss tlb pitfalls) and then the two analysis scripts.

### Supplemental cache/TLB counter capture
The Nov. 3, 2026 tagged WSL2 follow-up was collected with:
```bash
python3 run_experiments.py --only cache_miss,tlb --tag counters
```
It wrote `data/raw/cache_miss_counters.csv` and `data/raw/tlb_counters.csv`; all listed event columns in those files contain numeric values. The earlier driver version also overwrote the shared clock-estimate file despite `--tag`. The follow-up estimate is preserved as `data/raw/freq_estimate_counters.txt`, and the original estimate was restored from `RESULTS_TABLES.md`; the driver now tags the estimate file on future tagged runs. The preflight immediately before this capture recorded AC power offline; Windows power mode and Energy Saver state were not recaptured, so treat it as a separate supplementary capture. See Tables 10a-10b in `REPORT.md`. For tagged files, the plotting scripts still read the untagged CSV names; do not replace the original measurements unless you make a separate working copy.

## Where things are
* `REPORT.md`: the final report; main-suite numbers come from `RESULTS_TABLES.md` (generated by `make_results_tables.py`); the supplementary counter tables use the tagged CSVs named in Section 4.5.
* `data/raw/`: raw measurements (including `intensity_seq.csv`, `zero_queue_best.csv`, `zero_queue_saver.csv`, and the tagged `cache_miss_counters.csv`, `tlb_counters.csv`, and `freq_estimate_counters.txt` follow-up); `data/processed/`, `plots/`, `env/` (`cache_env.txt`, `preflight.txt`).
* `HYPOTHESES.md`: pre-experiment predictions and their rationale.
## Notes and limits
* **WSL2:** counter availability varies by configuration. The original run had no usable counter data; the Nov. 3 tagged follow-up did return numeric events. The CPU clock is estimated, not read; nested paging can distort TLB results.
* **THP:** the huge-page runs only mean something if `thp_kb > 0` in `data/raw/tlb.csv` / `zero_queue.csv`.
* Tools are custom (Intel MLC does not run on AMD); `stream_triad` is the independent cross-check.
* Single-run points (bandwidth, loaded latency) have no error bars; repeat the whole run on another day if time permits and say so.
